## Cross-component impact

- **`@eum/metafields` is consumed by both `frontend` and `onboarding`** (verified — both import from it). Adding two new exports is additive/non-breaking; no existing export signature changed. Backend does NOT consume the package (deliberate — local numeric mirror, same precedent as `MetafieldRole`), so the backend gate re-implements the truthiness check locally with a sync comment.
- **Backend gate change** affects guest, organization, and team onboarding completion — all three flow through the single `submit()` gate (confirmed: only one copy of the "required metafields" gate exists in the backend). Risk: a required-checkbox left `'false'` now correctly blocks completion (intended). No production/legacy rows to migrate — EUM 2.0 unreleased.
- **Additional Info edit** affects both guest profile and org profile pages (shared `AdditionalInformation` component). Checkbox `aadFieldName` is always empty (Settings dialog disables Entra mapping for Checkbox, FR-23), so enabling edit triggers NO `syncMetafieldEntraFields` Entra write-back side effect — the value persists to the DB like every other metafield edit.
- **Dialog modalType="alert"** changes ARIA role `dialog`→`alertdialog` for the two Settings Add/Edit dialogs only; delete-confirmation dialogs untouched. Existing tests updated to the new role.
